编译原理

一、形式文法​

形式文法是一种用来精确描述语言结构的数学工具。在编译原理中，它用于定义编程语言的语法规则。

1. 定义​

形式文法 GGG 定义为一个四元组：

G=(VN,VT,P,S)G = (V_N, V_T, P, S)G=(VN​,VT​,P,S)
  • VNV_NVN​ (非终结符集)：语法变量，表示抽象的语法结构，如 <表达式>、<语句>。
  • VTV_TVT​ (终结符集)：语言中实际出现的符号，如关键词 if、运算符 +、标识符。VN∩VT=∅V_N \cap V_T = \emptysetVN​∩VT​=∅。
  • PPP (产生式集)：形如 α→β\alpha \to \betaα→β 的规则集合，其中 α\alphaα 包含至少一个非终结符，β\betaβ 是终结符和非终结符组成的串。描述了如何将非终结符替换为符号串。
  • SSS (开始符号)：S∈VNS \in V_NS∈VN​，整个语法推导的起点。

从 SSS 出发，反复使用产生式替换，最终得到全部由终结符组成的串的过程叫推导。由文法 GGG 生成的所有终结符串的集合，称为该文法定义的语言 L(G)L(G)L(G)。

2. 乔姆斯基分类​

根据产生式形式的不同限制，文法分为四类，构成了乔姆斯基谱系。每一类对应一种自动机。

类型名称产生式形式限制对应的自动机计算能力与典型应用
0型无限制文法/短语结构文法α→β\alpha \to \betaα→β，α\alphaα 至少含一个非终结符，无其他限制。图灵机可枚举语言，编程语言极少直接使用。
1型上下文有关文法 (CSG)αAβ→αγβ\alpha A \beta \to \alpha \gamma \betaαAβ→αγβ，A∈VNA \in V_NA∈VN​，γ\gammaγ 非空。即 AAA 只有在上下文 α,β\alpha, \betaα,β 中才能被替换。线性有界自动机可描述某些非上下文无关特征（如变量先声明后使用），但解析复杂，实用少。
2型上下文无关文法 (CFG)A→βA \to \betaA→β，A∈VNA \in V_NA∈VN​。产生式左侧只能是一个单独的非终结符，替换与其上下文无关。下推自动机语法分析的核心。能描述嵌套、递归结构（如括号匹配、if-else 配对）。
3型正则文法 (RG)右线性：A→aBA \to aBA→aB 或 A→aA \to aA→a；左线性：A→BaA \to BaA→Ba 或 A→aA \to aA→a。有限自动机计算能力最弱，用于词法分析（标识符、常数、关键字模式）。

包含关系：3型 ⊂\subset⊂ 2型 ⊂\subset⊂ 1型 ⊂\subset⊂ 0型。

3. 表示方法​

在实际编写编译器的语法规则时，我们通常不直接写严格的四元组，而使用更直观的元语言。

  • BNF 范式：最经典的表示法。

    • → 写作 ::=
    • 非终结符用尖括号：<expr>
    • 多选项用竖线 |
    • 示例：<if_stmt> ::= if <expr> then <stmt> | if <expr> then <stmt> else <stmt>

  • 扩展 BNF (EBNF)：引入正则文法符号，使规则更简洁，但表达力仍属 CFG。

    • { }：重复零次或多次（Kleene星号）
    • [ ]：可选部分（出现零次或一次）
    • ( )：分组
    • 示例：<term> ::= <factor> { (* | /) <factor> }

  • 语法图：图形化表示，用有向路径表示规则。

    • 矩形框为非终结符，圆形/椭圆框为终结符。
    • 路径分支表示选择，回路表示重复。非常直观，早期 Pascal 语法常用。

二、自动机​

自动机是能够根据输入、状态和规则，自动执行计算的抽象数学模型。在编译原理中，它是识别语言、实现词法和语法分析器的理论基石。

1. 定义​

自动机通常被定义为一个五元组 M=(Q,Σ,δ,q0,F)M = (Q, \Sigma, \delta, q_0, F)M=(Q,Σ,δ,q0​,F)，不同类别自动机在此基础上有扩展。

  • QQQ：有穷状态集。
  • Σ\SigmaΣ：有穷输入字母表。
  • δ\deltaδ：状态转移函数，是自动机的核心规则。
  • q0q_0q0​：起始状态，q0∈Qq_0 \in Qq0​∈Q。
  • FFF：接受状态（或终态）集，F⊆QF \subseteq QF⊆Q。
  • （下推自动机还有栈字母表和栈操作，图灵机还有带字母表和读写头操作）

自动机从初始状态开始读输入符号，根据转移函数改变状态，读完所有输入后若处于接受状态，则称该输入串被识别/接受。

2. 分类与对应解析方法​

自动机的分类与乔姆斯基文法层级精确对应，每一类自动机恰好是识别该类语言的计算模型。

(1) 有限自动机 (FA) —— 对应3型文法/正则语言​

它的“记忆”只有有穷个状态，没有外部存储器。用于词法分析。

  • 分类：

    • 确定性有限自动机 (DFA)：对任一状态和任一输入符号，有且仅有一条确定的转移路径。δ\deltaδ 是一个单值映射。
    • 非确定性有限自动机 (NFA)：对同一状态和同一输入，可以转移到多个不同状态，或存在不消耗输入符号的 ε\varepsilonε 转移。δ\deltaδ 映射到状态集。

  • 解析方法 (词法分析的实现)：

    1. 对语言中的每种词素模式（关键字、标识符、数字等）分别构建正则文法或正则表达式。
    2. 将这些正则表达式统一转换成一个 NFA（用 Thompson 构造法）。
    3. 用子集构造法将 NFA 确定化为 DFA。
    4. 将 DFA 状态数最小化，得到最简 DFA。
    5. 编码这个最简 DFA 的转移表或控制流，成为最终的词法分析器，高效地、从左到右一趟扫描输入流，识别词素。

(2) 下推自动机 (PDA) —— 对应2型文法/上下文无关语言​

它在有限自动机基础上增加了一个栈，有了处理无限嵌套和递归的能力，记忆容量无界。是语法分析的理论模型。

  • 解析方法 (语法分析的实现)： 下推自动机是理论模型，实际编译器中用以下两种策略来模拟它，并用确定化的算法和表驱动实现。

    • 自顶向下分析 (Top-Down)

      • 思想：从开始符号出发，尝试推导出输入串，对应为输入串建立从根到叶子的语法树。
      • 代表算法：LL(k) 分析法（递归下降、预测分析）。
      • 特点：根据当前最左非终结符和未来 k 个输入符号（前瞻符号）无回溯地选择产生式。要求文法必须是 LL(k) 文法，不能有左递归和复杂二义。
      • 实现：手工递归下降简单直观；自动生成通常使用预测分析表驱动的下推自动机。

    • 自底向上分析 (Bottom-Up)

      • 思想：从输入终结符串出发，逐步归约，直到归约成开始符号，对应语法树从叶到根构建。
      • 代表算法：LR(k) 分析法（SLR, LR(1), LALR(1)）。
      • 特点：能处理比 LL 更广的文法类。通过维护分析栈和状态来跟踪已读入和归约的部分，通过“移进-归约”冲突解决表来决策。LALR(1) 是实际应用最广的（Yacc/Bison 采用）。
      • 核心：构造出分析动作表和转移表（ACTION/GOTO 表），驱动一个确定性的下推自动机。

(3) 线性有界自动机 (LBA) —— 对应1型文法​

图灵机在输入串长度范围内移动（不能超出）。计算能力受内存限制。编译很少直接使用。

(4) 图灵机 —— 对应0型文法​

具有无限长读写带的模型，是计算的终极抽象。决定编译器要处理的源语言整体性质（哪些问题是可判定的）的边界，但不用于具体实现。

三、编译过程中的联系​

编译阶段涉及语言类别理论模型输入输出典型生成工具
词法分析正则语言 (3型)DFA/NFA源代码字符流词法记号流Lex, Flex, 手写 DFA
语法分析上下文无关语言 (2型)下推自动机 (LL/LR)词法记号流抽象语法树 (AST)Yacc, Bison, ANTLR
语义分析等上下文有关 (1型) 或图灵完备 (0型)符号表、属性文法等综合手段AST带标注的 AST、中间代码手工编写为主

实战​

import re

# 定义词法单元的正则表达式模式
token_patterns = [
    ('NUMBER', r'\d+(\.\d+)?'),  # 匹配数字
    ('PLUS', r'\+'),  # 匹配加号
    ('MINUS', r'-'),  # 匹配减号
    ('MULTIPLY', r'\*'),  # 匹配乘号
    ('DIVIDE', r'/'),  # 匹配除号
    ('LPAREN', r'\('),  # 匹配左括号
    ('RPAREN', r'\)'),  # 匹配右括号
    ('WHITESPACE', r'\s+')  # 匹配空白字符
]

# 定义一个函数来进行词法分析
def lexer(expression):
    tokens = []
    pos = 0

    while pos < len(expression):
        match = None

        # 尝试匹配每个正则表达式模式
        for token_type, pattern in token_patterns:
            regex = re.compile(pattern)
            match = regex.match(expression, pos)
            if match:
                # 如果匹配成功，将匹配到的词法单元加入到tokens列表中
                value = match.group(0)
                if token_type != 'WHITESPACE':
                    tokens.append((token_type, value))
                pos = match.end(0)
                break

        # 如果没有匹配到任何模式，说明输入表达式存在非法字符
        if not match:
            raise ValueError(f"Invalid character: {expression[pos]}")

    return tokens

# 测试词法分析器
expression = "3.14 + 2 * (4 - 1)"
tokens = lexer(expression)
for token_type, value in tokens:
    print(f"Token: {token_type}, Value: {value}")


# 定义一个函数来进行语法分析
def parser(tokens):
    pos = 0

    # 辅助函数，用于解析数字
    def parse_number():
        nonlocal pos
        token_type, value = tokens[pos]
        if token_type == 'NUMBER':
            pos += 1
            return float(value)
        else:
            raise ValueError(f"Expected NUMBER, but got {token_type}")

    # 辅助函数，用于解析乘法和除法运算
    def parse_term():
        nonlocal pos
        left = parse_factor()

        while pos < len(tokens):
            token_type, value = tokens[pos]
            if token_type == 'MULTIPLY':
                pos += 1
                right = parse_factor()
                left *= right
            elif token_type == 'DIVIDE':
                pos += 1
                right = parse_factor()
                left /= right
            else:
                break

        return left

    # 辅助函数，用于解析加法和减法运算
    def parse_expression():
        nonlocal pos
        left = parse_term()

        while pos < len(tokens):
            token_type, value = tokens[pos]
            if token_type == 'PLUS':
                pos += 1
                right = parse_term()
                left += right
            elif token_type == 'MINUS':
                pos += 1
                right = parse_term()
                left -= right
            else:
                break

        return left

    # 辅助函数，用于解析括号表达式
    def parse_factor():
        nonlocal pos
        token_type, value = tokens[pos]
        if token_type == 'LPAREN':
            pos += 1
            result = parse_expression()
            if pos >= len(tokens) or tokens[pos][0] != 'RPAREN':
                raise ValueError("Missing closing parenthesis")
            pos += 1
            return result
        else:
            return parse_number()

    # 开始进行语法分析
    result = parse_expression()

    # 检查是否处理完所有的词法单元
    if pos < len(tokens):
        raise ValueError("Unexpected token")

    return result

# 测试表达式解析器
expression = "3.14 + 2 * (4 - 1)"
tokens = lexer(expression)
result = parser(tokens)
print(f"Result: {result}")
